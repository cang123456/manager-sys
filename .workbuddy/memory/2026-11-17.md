### 复用的验证手法（可再用）
- 已登录页面的 scoped 样式无法用静态 HTML 复现时：先从 `dist/static/css/*.css` 里正则取到组件的 `data-v-xxxx` 哈希（如 `\.logo-mark\[data-v-([0-9a-f]+)\]`），再在临时 HTML 的元素上写同名 `data-v-xxxx` 属性、link 整包 CSS，即可 1:1 还原渲染效果，用 Edge `--headless=new --screenshot --force-device-scale-factor=3` 放大核对。

## 17:41 第三轮：侧栏 Logo 「不居中」修复

现象：用户截图里侧栏顶部只有「管理系统」四个字，深色标记消失，下面还有一团被裁掉的残影。

根因：`sidebar.scss` 里 `#app .sidebar-container a { display: inline-block; width:100%; overflow:hidden }` 带 **ID 选择器（1,1,1）**，优先级压过 Logo 组件 scoped 的 `.sidebar-logo-link[data-v-x]`（0,2,0）。于是 logo 链接退化成 inline-block，标记与文字**上下堆叠**，第二行被 64px 容器 `overflow:hidden` 裁掉。

修复：在同一 `a` 规则里显式补 `.sidebar-logo-link { display:flex; align-items:center; justify-content:flex-start }`（1,2,1），并另加 `.sidebar-logo-container.collapse a.sidebar-logo-link { justify-content:center }`（1,3,1）保证折叠态居中。

**教训（本项目通用）**：`sidebar.scss` 的所有规则都包在 `#app` 里，优先级天然高于任何 SFC scoped 样式，改侧栏相关组件时**必须优先检查 sidebar.scss 是否有同名规则**，不能只改组件内的 style。

## 17:55 「点菜单空白、F5 才有内容」定位与修复

现象：SPA 内点击菜单进入 /system/user 等内容区全空；F5 整页刷新后正常。

根因：`AppMain.vue` 的 `<transition name="fade-transform" mode="out-in">` 包着 `<keep-alive :include="cachedViews">`。
TagsView 的 `watch(route)` → `addTags()` → `addCachedView()`（store/modules/tagsView.js:35）会在路由变化同一 tick 内改 `include`，
keep-alive 重新渲染把 out-in 的离场钩子打断 → 新页面停在 `fade-transform-enter-from`（opacity:0）→ 空白。
F5 是首次渲染，Vue 不会对初始渲染跑 transition，所以正常。属于时序竞态，改样式后首页变轻量才暴露。

修复：
- `AppMain.vue` 去掉 `<transition>`，只留 `<keep-alive>`（瞬时替换，Apple 本身也不做页面转场）。
- `views/index.vue` 补 `defineOptions({ name: 'Index' })`，原先空的 `<script setup name="Index">` 没有真正生成组件名，keep-alive 的 include 匹配不上。
- 顺带修 `apple.scss` 的 `--el-mask-color`：之前错误地设成 `rgba(0,0,0,.42)`，而 Element Plus 的 `el-loading-mask` 正是取这个变量 → 表格 loading 遮罩会被染黑。已改回浅色（暗色 `rgba(28,28,30,.9)`），弹窗遮罩另写 `.el-overlay { background-color: rgba(0,0,0,.42) }`。
